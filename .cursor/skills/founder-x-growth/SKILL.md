# Croissance X — comme un fondateur qui grandit vraiment

Un geste : dire **quoi publier cette fois** (répondre ou poster), avec accroche, preuve, appel doux. Puis rédiger via les deux autres recettes. Pas une usine. Pas un bot.

Arbre et portes : [`.cursor/skills/README.md`](../README.md). Les lire **avant**. Texte au registre → [`elon-musk-voice`](../elon-musk-voice/SKILL.md). Réponse qui touche → [`x-replies-that-hit`](../x-replies-that-hit/SKILL.md).

## Ce que les comptes qui grandissent font (et pas les cours)

- **Les réponses distribuent. Les posts identifient.** Sans réponses sous des comptes plus gros, le post original meurt. Sans post original de temps en temps, on n’est personne.
- **Cadence tenue, volume bas.** Quelques réponses nettes dans la journée > vingt posts vides. Un original seulement s’il y a une idée vraie.
- **Accroche = première ligne.** Le reste est optionnel. Pas de titre LinkedIn. Pas de fil « thread 🧵 ».
- **Preuve avant pitch.** Un fait du produit (étape qui ment, on n’entre pas dans l’appel, 129 $ / org) bat « AI sales coach ».
- **Appel doux, rare.** Lien [https://3xrep.com/install](https://3xrep.com/install) quand on le demande, ou quand le post l’a gagné. Pas sous chaque réponse.

Ce n’est **pas** : pods, achat d’abonnés, « drop a fire if », sondage pour le sondage, growth hack, Grok Build, message privé de prospection.

## Avant

1. Portes du [README](../README.md) : brouillon jusqu’au **go** (compte X marque + install qui encaisse + oui explicite). Pas de message privé. Marque seulement. 129 dollars, pas 99 euros.
2. Contexte **défaut** : `README.md` + accueil + `/install`. Repo plus profond seulement si une claim cloche. Web seulement si le sujet vit.
3. S’il n’y a pas encore de compte X 3xrep : le dire en ligne 1. Écrire les brouillons quand même. Ne pas inventer un handle.

## Recette

1. **Choisir le geste du tour** — un seul :

   | Geste | Quand | Sortie |
   | --- | --- | --- |
   | **Répondre** | Un post vivant (outil, concurrent, « le CRM est vert », Gong, agent VP) où 3xrep a un fait, pas un slogan | 1–5 brouillons de réponses ([`x-replies-that-hit`](../x-replies-that-hit/SKILL.md)) |
   | **Poster** | Une idée qui tient sans le tweet des autres | 1 original ([`elon-musk-voice`](../elon-musk-voice/SKILL.md)) |
   | **Skip** | Rien à ajouter, ou ce serait du pitch | Une ligne : pourquoi on se tait |

   Par défaut : **répondre**. Original si l’idée est déjà là (pas « il faut poster aujourd’hui »).

2. **Accroches (posts originaux seulement).** Trois max. Test : la première ligne se comprend seule, et un fondateur sales la retweeterait sans nous connaître. Tuer : *excited*, *game-changer*, *introducing*, hashtags, emoji de lancement.

3. **Preuve.** Coller **un** fait tenu (home / install / README). Exemples qui existent : on n’entre pas dans les appels ; 129 $ l’organisation pas le siège ; l’étape « Negotiation » sans qui signe est illégale ; une URL dans l’agent, pas un onglet CRM. Pas de logo client. Pas de capture inventée.

4. **Appel.** Compter : 0 ou 1 lien install dans tout le tour. Si 1 : le post original, pas les cinq réponses.

5. **Cadence proposée (conseil, pas un cron).** Réponses : qualité, quelques-unes, sous des posts du métier (ventes, CRM, agents) — pas sous des célébrités hors sujet. Original : 0–3 par semaine, seulement s’il y a matière. **Rester sous son propre post** s’il est publié un jour (répondre aux réponses). Aujourd’hui : tout est brouillon.

6. **Rédiger** avec l’autre skill. Ne pas livrer un calendrier de 30 cases vides.
