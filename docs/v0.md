# V0 / V1

Figé. 1er septembre 2026, soir. Gagne sur [loop.md](loop.md) et [chemin.md](chemin.md) tant qu’on n’a pas de carte CRM.

## Slice

On rend le cerveau dispo là où ils travaillent déjà : **Claude (Cowork inclus), ChatGPT Business, Notion (Custom Agents / MCP)**. Pas d’UI 3xrep. Pas d’app HubSpot. Pas de bouton sur la fiche.

Ils parlent à **leur** agent. Cet agent a déjà le CRM (connector HubSpot / Salesforce / Notion officiel). On ajoute 3xrep. C’est tout.

La [sortie](sortie.md) s’affiche dans ce chat. Pas ailleurs.

## Qui

Entreprises déjà sur une de ces plateformes, **en plan équipe** (Claude Team, ChatGPT Business, Notion avec agents), CRM déjà branché ou branchable en connector.

Pas besoin d’un sales ops comme métier. L’admin = le owner du workspace (souvent le founder / HoS). Il ajoute 3xrep **une fois** à l’org. Chaque personne **Connect** ensuite avec *son* compte CRM — elle ne voit que ses deals. C’est voulu, pas un bug.

Hors V0 : l’équipe dont les AE ne sortent jamais de HubSpot. Ça, c’est V2 (carte). On ne les chasse pas maintenant.

## Admin vs tout le monde

| Plateforme | L’admin fait | Chaque user fait |
| --- | --- | --- |
| Claude Team / Cowork | Owner ajoute le custom connector 3xrep (URL) + active le connector CRM | **Connect** (OAuth à son nom) |
| ChatGPT Business | Admin publie l’app MCP 3xrep sur le workspace + CRM | Pareil, auth individuelle |
| Notion Custom Agents | Admin autorise le MCP 3xrep, colle le spec sur l’agent partagé | Auth si le serveur le demande |

« Un admin, tout le monde parle au CRM » = le connector est **disponible** pour l’org. Ce n’est pas un seul token HubSpot partagé (ça casserait les droits). Enterprise-managed auth (Okta, Claude) = plus tard, si on l’implémente.

Il faut **un spec partagé** (Project Claude / GPT / agent Notion) : [spec-agent.md](spec-agent.md). Posture [icp.md](icp.md) + contrat [sortie.md](sortie.md) + choix de méthode. Sinon chacun a un Claude générique, pas 3xrep.
